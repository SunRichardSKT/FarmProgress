# Farm Progress：实时监控、提醒与房主授权修改方案

日期：2026-11-02。当前版本：1.6.6。已实现实时监控、具名提醒、收获/浇水/喂食方向指引、自定义范围、F8 设置与鼠标接管、所有访客自动授权、资产/库存及单格维护修改，以及一键 OTA 安装器。实际交付范围与验证限制见 [最新版说明](release-1.6.6.md) 和 [项目说明](../README.md)。以下保留后续功能规划，不能将规划项目视为全部已实现。

## 1. 产品结构

保留 F8 农场面板、F9 报告导出，增加实时概览、待办提醒和地图筛选。独立的管理面板通过组合键打开，包含数据调整、访客授权和操作记录。

常规监控始终只读；提醒与执行操作分别提供。点击提醒查看位置和详情，不自动收获、浇水或喂食。

## 2. 实时监控

| 页面 | 展示内容 |
| --- | --- |
| 概览 | 农场名称、房主/访客身份、等级、资产、季节天气、库存/容量、最近更新时间及同步状态 |
| 待办 | 可收获数量、缺水数量、缺料动物圈、即将成熟批次，按任务相关性、紧急程度、距离筛选 |
| 生长列表 | 品种、数量、所在区域、成熟数量、水分、饲料、预计成熟时间 |
| 地图 | 可收获、缺水、缺料、任务目标图层；点击条目高亮区域并显示坐标 |
| 任务 | 各目标还需收获数量、目前可收获数量、可用目标所在位置 |

小型悬浮条可独立开关，例如“可收获 128 格 · 缺水 42 格 · 缺料 3 圈”。可拖动、缩放、隐藏，在管理面板关闭时仍可显示。

计数区分“种植格数”和“可执行工作单位”：动物按圈内品种汇总共享饲料，鱼塘按整塘规则展示，避免重复提醒。仅对已解锁且当前可作业区域产生待办；其他区域可作为参考统计。

刷新目标：概览约 1 秒，待办增量更新约 2 秒，全量校准约 30 秒。以上为初始参数，需实测大农场后调整。游戏数据在主线程分批读取，不每帧扫描全图，也不反复生成完整导出文件。

访客面板明确标记“当前客户端观测”；房主摘要可用于比对。出现同步分歧时标记数据待核实，不把单纯网络心跳正常显示为数据一致。

## 3. 提醒规则

| 提醒 | 默认规则 | 点击后的内容 |
| --- | --- | --- |
| 可以收获 | 从未成熟转为成熟；同区域、同品种合并 | 数量、位置、关联任务 |
| 即将成熟 | 预计剩余时间跨过用户设置的提前量，默认 5 分钟 | 时间估计、估计依据 |
| 需要浇水 | 未成熟、非灌溉地格，水分降至 10% 以下 | 品种、水分、位置 |
| 需要喂食 | 同圈同品种饲料耗尽且仍需成长 | 动物圈、品种、当前饲料 |
| 饲料不足 | 当前饲料不足以支持该组动物本轮全部成熟 | 饲料缺口；区别于已经断粮 |
| 任务可推进 | 任务所需品种出现可收获目标 | 对应目标和可收获数量 |

提醒方式：游戏内轻提示和待办列表默认开启；提示音可选。桌面通知放到后续版本。

加入农场先显示一次待办摘要，不逐格补发历史提醒。持续缺水等状态不每次刷新都弹窗；默认同类同区域冷却 5 分钟，支持稍后提醒、静音和最低数量门槛。状态恢复后再次恶化才重新触发。阈值附近采用恢复缓冲，避免水分微小波动反复提示。

优先级默认为：动物断粮、任务目标可收获、其他可收获、缺水、饲料不足预警、即将成熟。用户可以调整。

成熟时间作为估计显示：浇水、天气、季节或修改后重算；动物供料不足时显示“需继续喂食，时间未定”。作物缺水文案描述对成长的影响，不宣称必定枯死。监控仅在游戏运行且农场加载时有效。

## 4. 管理入口

建议默认 Ctrl + Shift + F10，可在配置中改键，最终需要实机核对按键冲突。普通面板不显示修改器入口。

组合键只打开面板，不直接执行修改；聊天输入、重绑按键和加载期间不响应。Esc 关闭。重新加入农场后面板恢复关闭。

房主打开后看到完整管理项；获授权访客只看到允许的功能；未授权访客看到“未获房主授权”。隐藏入口用于避免误触，权限校验在房主端完成。

## 5. 数据调整项目

| 功能 | 操作形式 | 建议阶段 |
| --- | --- | --- |
| 金币、钻石、奖牌、票券 | 增减或设置目标值，预览修改后余额 | 第一批修改功能 |
| 分类库存 | 设置指定资源数量，遵守实际容量限制 | 第一批修改功能 |
| 补水 | 当前选择区域、同品种或全农场，一次性补满 | 第二批 |
| 补充饲料 | 指定动物圈与品种，一次性补充 | 第二批 |
| 成熟调整 | 对选定作物、花、动物、鱼执行一次性调整 | 第二批，逐类验证 |
| 农场经验/等级、物品经验 | 通过游戏升级逻辑调整并刷新关联状态 | 后续 |
| 持续免浇水、免喂食、生长倍率 | 房主运行的持续规则，界面持续显示启用状态 | 后续 |
| 建筑进度、地块解锁 | 需要同时处理关联状态和同步 | 后续独立评估 |

金额使用游戏支持的整数范围，界面不经过浮点数计算。经验调整不只改显示等级；成熟调整不直接发放收获收益，实际收获另行执行。

“按原游戏费用远程浇水/喂食”和“管理员直接补水/补料”是不同操作，界面明确说明费用。修改项默认以本次操作生效；持续规则默认仅本次会话启用。

操作前显示农场、目标区域、数量、当前值和目标值。普通小范围调整一次提交；全农场和大额操作增加一次预览确认。

## 6. 访客授权和远程操作

这里的远程操作定义为访客已加入房主当前房间后，通过 Mod 提交请求。首版不建设浏览器控制台，也不支持房主离线时修改。

默认对所有进入房间的访客自动授权，赋予房主当前开放的数据修改功能使用权限，无须逐个添加玩家或逐次人工审批。房主仍可在在线玩家列表中调整个别玩家的权限，支持以下权限组合：

- 观察员：监控和提醒。
- 农场助手：房主选定的补水、补料等维护操作。
- 数据管理员：房主选定的资产和库存调整。
- 自定义：按功能、单次额度和目标区域授权。

针对房主长期挂机、脚本自动重启房间的使用场景，采用持久化自动授权：在配置过的农场默认开启，保存后重启游戏或重建房间均自动恢复，无须房主再次按组合键或确认。逐次审批默认关闭，可按类别另行启用。

授权对象默认选择“所有加入房间的访客”，首次使用不要求手动切换模式或添加名单，新访客加入即自动获得当前开放的修改权限。可选改为指定玩家名单或 Steam 好友；名单按平台稳定身份识别，不按昵称识别，好友模式需要房主端能够可靠查询好友关系。功能、额度与区域使用房主保存的配置；所有访客自动授权模式在游戏或房间重启后自动恢复。

授权配置保存在房主本地，按房主账号和稳定农场标识关联，不依赖重启后变化的房间 ID；若无法可靠匹配农场，不把其他农场的授权套用过来。房主可以随时撤销某人权限；撤销记录同样持久保存，自动授权时优先排除。

与自动重启脚本的配合流程：启动游戏 → 脚本进入目标农场并建立房间 → Mod 等待农场加载完成 → 读取该农场授权配置 → 完成兼容性检查 → 自动接受已授权访客的请求。自动授权只恢复权限，不自动打开管理面板，也不自动修改任何数值。脚本原有的进房流程可以继续使用；如需脚本查询 Mod 是否就绪，可后续提供简单状态接口。

房主不在电脑前不影响授权和执行，前提是游戏仍运行、已进入该农场并正常提供房间。重启或加载期间显示“房间暂不可用”，就绪后自动恢复。访客断线后的自动重连属于另一项功能，本方案不把它视为游戏已有能力。

流程：访客提交操作及请求编号 → 房主 Mod 自动检查身份、权限和当前目标 → 按顺序执行 → 向客户端同步 → 返回执行结果。访客显示“等待房主响应 / 执行中 / 已完成 / 已拒绝 / 结果待核实”；只有明确配置为逐次审批的类别才显示“等待人工审批”。

已预授权的操作不要求房主每次确认。请求按编号去重；等待超时后查询原请求结果，不直接重复执行。过期的目标或余额预览返回重新确认，避免多人同时操作覆盖新的状态。

房间重启后建立新的会话标识，旧会话的待处理请求不自动重放。已发送但未确认完成的操作标记为“结果待核实”，访客重新读取当前状态后决定是否新建请求，避免重复加钱或补发操作。授权持久化不代表把上次点击的修改命令保存为开机任务。

## 7. 联机一致性要求

现有代码分析显示：加入房间时接收完整农场，之后主要重放工作操作。仅改访客本机字段不能成为可靠的共享数据修改方案。

监控可沿用单端安装；任意数据修改模式首版要求房主和所有参与模拟的客户端安装兼容 Mod。未安装客户端也可能因自定义调整而分歧，不能只要求修改发起者安装。

进入修改模式前协商版本和能力。不具备完整兼容条件时，不执行自定义数据修改；仍可监控，或使用已验证可通过原生操作同步的普通作业。新玩家加入时重新判断兼容条件，必要时暂停修改。

房主校验并排序命令；客户端在明确的模拟边界应用同一变化，再核对相关资产、地格或动物圈状态。具体传输接口、暂停/排序与恢复机制需要实现前验证，不能视为已存在能力。避免为每次微小调整传输整张农场。

出现差异时停止后续修改，显示需要恢复同步；现有原生重进流程可作为恢复入口。随机种子相同不足以证明资产和地图一致，需要核对本次修改涉及的状态。

## 8. 操作记录与恢复

房主记录操作者、时间、请求编号、修改前后值、范围及结果；访客可查看本人请求记录。先覆盖简单资产和库存调整的条件撤销：相关值未被后续操作改变时允许恢复。成长、任务结算、奖励发放等不承诺通用撤销。

首次开启数据修改会话前生成房主农场备份，并在面板展示备份位置。完整恢复在退出房间后进行，不在访客仍在线时热替换存档。

## 9. 分期与验收

1. 实时概览、分组待办、三类基础提醒和地图定位，保留现有导出。
2. 房主管理入口、会话备份、资产/库存调整、操作记录。
3. 能力协商、访客授权、请求回执、多端应用与状态比对；通过后开放访客修改。
4. 逐类增加补水、补料、成熟调整；最后评估持续规则。

监控验收：大农场刷新不卡顿；完成浇水/收获后待办消失；同圈/同塘不重复统计；提醒不刷屏。

联机验收：房主、授权访客、另一个观察客户端同时核对修改结果，并在保存重进后复查；首次使用时，新访客无需添加名单即可获得开放的修改权限；重复请求只执行一次；撤销授权后新请求被拒绝且重启后仍被拒绝；不兼容客户端加入会暂停修改；断线或同步差异时不误报成功。自动重启验收：正常重建房间及游戏异常退出后，目标农场的所有访客自动授权模式恢复；其他农场不继承该农场的自定义授权配置；访客无需房主人工作答即可操作；旧会话未完成请求不自动重放。

当前仓库对部分已有功能仍注明待真实双人验证，因此此方案中的实时性能和新联机协议都属于待验证设计，不构成已可用承诺。
